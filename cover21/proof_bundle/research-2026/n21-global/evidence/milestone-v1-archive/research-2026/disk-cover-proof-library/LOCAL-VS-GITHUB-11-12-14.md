# 本地与 GitHub 的 n11、n12、n14 证明：对比与取舍

2026-10-03。GitHub固定提交：
`089584973f41e6374ce110f6e5b5ee456df19352`，
本轮查询远端HEAD仍是该提交。下述对比来自数学正文、源码结构、
本地证据记录的逐项阅读，不是把GitHub所有证书重新运行了一遍。
没有修改或启动本地n11形式化，也没有派子代理。

## 结论先行

**不是“网上证明更短，所以替换本地证明”。**
本地路线擅长用问题特有的几何结构压缩困难域；GitHub路线更适合
做可移植、可独立重放的通用工具。两套都必须支付“任意覆盖进入
所验域”的归约，程序退出0不能代替这一点。

- n11：本地后期几何压缩非常有效，最终候选树远小于GitHub；
  GitHub的普通Voronoi归约和简单三角剖分目录更统一，但它的多应力
  局部分析和候选树并不简洁到可以无成本替换现有Lean路线。
- n12：GitHub候选型的一条正应力**全域严格凸性**是最值得借鉴
  的数学简化；本地最费力的两内部盘原子容量分支在GitHub中改由
  通用图分类/能量证书承担。它显著减少了专用接口，但仍有组合
  完整性、132残余类型和符号应力结构的认证义务。
- n14：GitHub的**只限制锚点、无需自由圆心接近**的隔离引理，
  适用半径1/6或7/40，比本地先全域压进2e-6弧度格再接局部定理
  的路线更容易维护。其较小树和简洁整数验算结构最适合向n21推广。

因此n21采用融合路线：本地精确有理覆盖/候选资产，通用的不可约
Voronoi归约、带安全剪枝的穷尽剥离、逐杆力证书及锚点隔离。
本地几何/容量界用于进一步剪枝，而非假定n21是某个对称族。

## 1. 数学对象、作用域与状态

| 项目 | 本地 | GitHub |
|---|---|---|
| n11精确根 | 7个几何变量+5乘子，共12未知；半宽/方向三角函数及正根分支 | 110元二次KKT，45活跃杆、8圆约束、56几何坐标及t |
| n12精确根 | F=G=H=T=0 的4元有理多项式根 | 14元对称商KKT，7种应力轨道；多项式不全是二次 |
| n14精确根 | z,c,r 的3元含正根式系统，驻定H=F_zG_c−F_cG_z | 116元二次KKT，44杆、9圆约束、62几何坐标及t |
| 竞争构型 | 三者最终主链均明确任意平面圆心、重复/退化、不预设对称 | 三者正文也明确任意更小覆盖，不预设候选对称 |
| 本地状态 | C924/C1141/C1372源证明；本轮只读，未重跑全部继承依赖 | 本轮仅阅读/比较这些阶数，未全量重放或核验与本地根的精确同一性 |
| 形式化 | n11在另一台电脑推进，尚不能说整个主定理Lean完成；n12/14暂停 | 文档明确不是Lean/Coq，也不是外部同行评审 |

三个半径的显示位数一致：
n11约0.3799838531198386897、n12约0.3611029637445086441、
n14约0.3317320342762341226。**小数前缀一致不证明代数根同一性**。
若要互换根证书，必须构造精确坐标变换、验证方程恒等式及唯一盒
包含，或分别完整证明两者都是同一优化问题的最小值。本轮未把这项
比较义务偷换成“已完成独立验证”。

n12几何变换有明确线索：本地a对应GitHub内部轨道w，本地t对应v，
本地高圆心横坐标b对应u c，本地辅助参数w_aux对应z u s；
公共几何方程可推出 `u c=(1+w+r)/2`。但包括本地驻定T和完整
隔离盒的精确身份检查仍未在本轮认证，故不据此更改根定义。

## 2. 无条件全局归约

### n11

本地先以C450的两圆加权容量排除10边界+1内部，强迫9+2。
同实际弧的内根替换保留全覆盖，再重建最近点所有权；
容量/连通性证明两个hub正长度邻接，环局部性、耳计数及各完整
度数类证书最终压成一个无弦6/7双扇图。这里的优势是强剪枝，
不是初始假设最优构型9+2。

GitHub则留出严格半径余量，扰动普通Voronoi、取不可约子覆盖，
由私有点不返回得到简单盘对偶。B≥9、至少1内部，直接枚举
(9,1),(9,2),(10,1)三个族，共3843轨道；3788个Farkas排除。
它不需要本地复杂的hub邻接和耳分类引理，但需要完整图枚举的
有效性/去重/质量总数检查，不能仅信任翻边搜索停止。

**取舍：** 本地归约数学义务更多、更难解释和形式化，但认证域
显著压缩；GitHub归约更少依赖专用容量核，规模代价在后面的树。

### n12

本地以边界活跃数k=9/10/11分类。k9的56网络中候选333锐利；
k11严格排除。k10归一化两hub，严格间距及核心覆盖给3维完整盒：
7041终端盒=318不可行+6723原子容量证书，无pending。
原子权值、ring中心的完整环带扫描、筛选参数与复用行 provenance
都是承重接口，不是“LP算出了正间隙”即可。

GitHub把不可约普通Voronoi全部归成6族：
(9,1),(9,2),(9,3),(10,1),(10,2),(11,1)，共38208轨道；
38076个Farkas排除，131个非候选能量证书。
候选9+3用正应力的Kron电导表达，在整个角多面体给出统一Hessian
正下界。固定锚点的有理LDL正性，再加同根等值和驻定，证明全域
极小；不需要局部盒收尾，也不需要k10原子容量扫描。

**取舍：** n12 GitHub候选数学机制更简洁，公开工具的入口更紧凑；
本地原子测度路线有不同的排除机制，可作为重要交叉研究材料。
不同机制不自动等于完全独立验证：仍可能共享候选、普通几何、
运行时或上游文献，且本轮未重放GitHub全链。

### n14

本地处理退化/隐藏边界单点、有限Cartesian见证目录，
q10/m4的879型成为唯一候选。连续半空间域多轮排除，
精确运输、线性对偶角界、平衡仿射流二次下界把完整域送入
2e-6弧度锚点格，再接62维站点/局部接口。原始全图的16个面
仍须保留；不能拿一个flow核心替代下游局部定理输入。

GitHub对四族(10,4)…(13,1)完整审计1313024轨道，
1305792度量排除，7231非候选与一个候选。
候选44杆的增广矩阵直接证明只要锚点距离≤1/6（替代包7/40），
全部正权核心坐标相同；不需要先证明自由圆心在小盒中。

**取舍：** GitHub n14的全局→局部接口更少、整数验算更统一。
本地仿射flow全域二次界仍很有价值：可用于n21远域剪枝或扩大
隔离域；若全域树增长，不能仅依赖二分，需要这类结构界。

## 3. 证书规模：不能只比一个“叶数”

| 对象 | 本地最终链 | GitHub文档所列链 |
|---|---|---|
| n11最终候选域 | 2505二分，2386能量叶+120局部叶，371有理场 | 106136基础叶；5302余根盒→304708细分节点，153052严格叶+1953局部叶；另53型13789叶及轮图 |
| n12关键困难 | k10 7041终端hub盒；每原子叶还有ring完整细分 | 38208拓扑先筛到132；131非候选能量证书、候选全域凸性 |
| n14候选及非候选 | 多轮半空间外域树/运输、flow、局部AD的组合链；不存在一个可与右栏相当的单叶数 | 主包候选913节点、非候选16075；替代包599、11621 |
| n14局部域 | 2e-6弧度锚点格，需实际坐标接口 | 1/6或7/40锚点Frobenius弦距 |

最后一行的单位、维数和几何定义不同，**不能直接给“扩大几万倍”
的精确倍率**。可以确定的是右栏容许明显较宽的全锚点邻域，
因而局部进入义务更容易满足。

不能把本地 n11的2506叶和GitHub总叶作整链成本精确比值：
本地还有C450、拓扑类和根/局部核；GitHub还有基础筛选与普通类型。
同样本地n12一个原子叶不是GitHub一个角能量叶的等价工作单位。
本轮没有同机同条件完整测速，所有仓库旧运行时间仅作源报告，
不报告“快多少倍”的新benchmark。

## 4. 严谨性、维护与形式化优劣

本地优点：

- 专用几何压缩强，n11最终树小；n12的容量原子提供另一种下界工具；
  n14的自适应flow/二次域桥有推广价值。
- 主链显式记录了真实Voronoi见证、退化处理、图/坐标运输、
  同根阈值和复用来源，能追到历史反例与修正。
- 当前n11 Lean已经有大量可用引理。贸然切换到另一根系统或图
  编号，会破坏已付形式化工作，不能只凭“体系更统一”就重启。

本地代价：

- 大量阶段目录、claim接口、镜像/旋转编号与旧状态交错，复现入口
  不如单包集中，曾有n14顶层索引落后于实际源证明的问题。
- 条件数、半宽、弧长、站点坐标与有效应力运输层次更多；
  非专家难以辨认哪个“全局”是oracle域，哪个是任意覆盖域。
- n14根虽维数小，根式和高阶AD的形式化义务不见得比大二次系统简单。

GitHub优点：

- 包级固定输入、明确通用图与验算入口；较容易在新环境独立重放。
- n13–n16的通用二次根、逐杆力与锚点隔离接口已在本机实际应用；
  n17–n20的部分状态安全剪枝避免显式列出全部未剪枝图，适合n21。
- 面数/杆数/独立角维数有明确区分；环流压缩再全图重算散度
  可以减小n21证书体积，不改变接受条件。

GitHub代价与审查点：

- n11仍有四维应力族、8维局部Taylor及大型候选树，不是统一的
  “大隔离矩阵一招”。
- n12旧枚举完整性正文引用Brown闭式及翻边论证；推广时应改用
  自行证明的根边递推、有效性/轨道质量，而不是继承一句“完整”。
- n14主包上界含两个塌缩三角形，须保留允许折叠的拓扑论证；
  替代包删掉塌缩面后34正向面更易读。包的面表/索引不可混用。
- 所谓“independent audit”常是同包中DFS/BFS或两套相关脚本，
  不是外部独立团队；共享三角函数核或存储结构必须说明。
- 核验Python的assert、整数算术和C++并不自动变成Lean定理。
  任意覆盖归约、剥离归纳、绕数、收缩和矩阵隔离仍需正式数学证明。

## 5. 对n21的具体选择

1. 候选来自本地资产，不需要n20最优性作为前提。
2. 精确根用无正权自由圆心剔除后的二次KKT，避免奇异系统。
   n21数值构型已发现一个内部“可动圆心”：不会声称全部21个
   圆心或所有最优构型唯一。
3. 全盘上界：核心同根等式+严格有理松弛面见证+固定可动圆心，
   用覆盖引理、定向/绕数及圆弓验证。
4. 下界：初始通用归约进入(B,I)=(12,9)…(20,1)九族；只用经严格
   验证的n21有理半径阈值产生新角隙剪枝，不复制n20数字常量。
   本轮后来把本地开核心容量与新六盘辅助力证书结合，
   已缩成B12/13/14三族。这是融合方法的具体收益，而非口头推荐。
5. 先在较小族关闭剪枝核对独立计数，再对完整九族执行穷尽剥离；
   任意节点上限/时间停止都保留为pending，不能输出完成标志。
6. 若固定应力不能全域凸，结合整数力分离、局部隔离及本地自适应
   flow，分别证明非候选和候选全连续域。

本轮n21已完成精确根、全盘达到、92维隔离及4817节点的全候选
角域下界；三族全目录与全部非候选仍未闭合，不能报n21无条件最优。
