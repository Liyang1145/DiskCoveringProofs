# Conditional stage admission: executor identity is a separate obligation

A complete current inventory proves that recorded bytes are unchanged. It
does not prove that the indicated acceptance program ran, that the program
ran the required rejection controls, or that its mathematical scope matches
the source partition.

For continued Rstar enumeration, accept a stage only after:

1. A fresh sealed bundle has been built from the actual accepted source
   frontier, its separately published replay and the unchanged radius basis.
2. Each native event has been executed with its actual output path; the launch,
   output, trace and kernel hashes are bound. Copied launch records must not
   be relabeled as new executions.
3. The sealed conditional acceptance executor has run. Its acceptance reports
   its own filename and hash where supplied by the schema. A delegated semantic
   replayer is bound separately, never relabeled as the executor.
4. The actual stage has passed all 32 regular-ring positive controls and all
   nine conditional rejection controls. A prior five-control force report or
   a metadata conversion cannot satisfy the missing actual controls.
5. A second invocation of the same sealed executor to a fresh report path has
   reproduced the acceptance. The original sealed files are not overwritten.
6. Fresh native terminal catalogue checks, actual catalogue replay, complete
   current-chain composition and an independent final inventory rehash pass.

`audit_conditional_stage_acceptance_contract.py` checks the metadata contract
and six rejection cases. It is an admission diagnostic only; it never replaces
the full conditional semantic replay or credits new geometry.

The historical stage19 compatibility bundle and chains derived from it are
retained as evidence of an insufficient admission attempt, not as completed
authoritative sources. The repair builds stage19-sparse-v2 directly from the
accepted stage18 lineage, reruns its native events and invokes the known
sealed sparse conditional executor with all controls. No compatibility
acceptance is manufactured, rewritten or adopted in that repair.
